# HI, JACK LIVE — состояние проекта на 12.11.2026

## Источник истины
Оператор предоставил архив `HI-JACK-LIVE-v0.3.5-EDGE-LIFECYCLE-FIX(2).zip` как актуальную рабочую копию. В нём есть **две расходящиеся папки модулей**:
- `HI_JACK_LIVE/modules/` — устаревшие исходники (например, `hj_media 0.1.1` и `hj_players 0.3.2`);
- `HI_JACK_LIVE/dist/HI_JACK_LIVE/modules/` — фактически развёрнутые версии (например, `hj_media 0.1.6`, `hj_players 0.3.10`).

**Критично:** для следующих изменений нельзя считать базовую исходную папку `modules/` актуальной без выравнивания с развернутой копией. Присланный оператором ZIP — исходный эталон текущего состояния; этот документ НЕ означает, что все его файлы уже загружены в GitHub.

- Автозапуск MediaMTX с приложением и корректное завершение процесса при выходе.
- Проверки полного отката ZIP-модуля, восстановления пользовательских настроек и стабильности Windows-приложения.
- Запуск независимых CI-тестов и Windows EXE из **выровненных актуальных исходников**.

## Технические особенности
- OBS Studio выполняет приём/микширование видео и аудио, запись и трансляцию. HI, JACK LIVE — локальная программа управления оверлеями и модулями.
- Сервер приложения: `http://127.0.0.1:8765/`.
- MediaMTX: RTMP 1935; RTSP 8554; Control API обычно 9997, поток `dji`.
- Собственный MediaMTX можно останавливать/перезапускать; внешний разрешено только мониторить.
- `hj_update_fix 1.0.0` — временное модульное исправление перемещения резервных копий между разными дисками (`WinError 17`). Нужно перенести исправление в CORE после отдельной проверки.
- Установленный бинарный MediaMTX и Windows EXE — внешние/собранные артефакты, их не следует хранить как исходный код в GitHub.
- Упаковка обновлений модулей: ZIP с одной папкой `hj_*`, контрактами, документацией, тестами и `checksums.json`.

## Правило публикации
Текущий документ — **реестр фактического состояния**, не новая сборка и не отметка о завершении HI, JACK LIVE 1.0. Чтобы ветка стала источником рабочей версии, нужно перенести именно развёрнутые исходники из архива оператора, протестировать и затем отдельно обновлять `main`. Не копировать в репозиторий локальные данные, секреты, EXE и полную папку `dist/`.
